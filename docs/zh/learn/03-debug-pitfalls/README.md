# 03. Debug 踩坑指南

很早之前就有老师告诉过我: 倘若一个人有10分的功力, 那么他实际上只能写, 也应该写6分的代码. 因为如果他用自己能力的极限写10分的代码, 那么将没有余力debug, 也没有能力review整个项目. 

当然在AI时代下, 这句话的可靠性值得商榷. 然而, 在实现这个项目的过程中, 踩的坑真是不胜枚举, 消耗了大量的时间和精力. 有好几次, 连续调试了2天都没有任何进展, 差点放弃. 由于是自定义架构, 很多bug在作者完成项目时, AI(GPT 5.3)不能有效定位问题, 或者只能提出一些假设, 仍然需要人手动复现问题, 古法解决.

因此, 在此处挑选了三个我认为比较有代表性, 且记忆比较清晰的debug过程(只是遇到所有困难的沧海一粟), 记录本项目真实发生、逐个解决的 debug 过程。

```
03-debug-pitfalls/
├── README.md
├── 01-hardware-pitfalls.md   硬件部分踩坑（内存字节对齐 / 异步读 / 掩码位）
├── 02-software-pitfalls.md   软件部分踩坑（UART 缓冲共享 / 输入所有权令牌）
└── 03-hw-sw-co-debug.md      硬软结合 Debug 完整实录
```
