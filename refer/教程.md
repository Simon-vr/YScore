### 准备工作

在 Ubuntu/Debian（或 WSL）上安装工具链（新加坡网络应该很快）：

```bash
sudo apt update
sudo apt install qemu-system-riscv64 binutils-riscv64-linux-gnu gcc-riscv64-linux-gnu make gdb-multiarch
```

验证：

```bash
riscv64-unknown-elf-gcc --version
qemu-system-riscv64 --version
```

推荐工具：用 VS Code + RISC-V 插件（或单纯终端 + make）。

### 第1部分：从零散汇编 → 工程化基础（建立 Makefile + 链接脚本意识）

**核心概念复习**：链接脚本决定代码放在哪里（QEMU virt 机通常入口 0x80000000）、启动代码（_start）设置栈、跳转 main、MMIO 直接操作 UART（0x10000000）。

#### work1

- 跟着这个极简博客走（代码最少，最适合温习）：
  - https://popovicu.com/posts/bare-metal-programming-risc-v/
- 实操：
  1. 手写 `hello.s`（用 `addi`/`sb` 写 UART 输出 "hello"）。
  2. 手写简单 `linker.ld`（把 .text 放在 0x80000000）。
  3. 写最简 `Makefile`（as + ld + qemu-system-riscv64 -machine virt -nographic -kernel xxx.elf）。
- 目标：改一个字符、改输出字符串，都能立刻看到效果。
- 额外：用 `riscv64-unknown-elf-objdump -D xxx.elf` 看反汇编，观察地址。

#### work2

- 视频（强烈推荐，边看边敲）：
  - Risc-V Bare Metal Assembler Hello World! → https://www.youtube.com/watch?v=qLzD33xVcRE
  - 对应 GitHub：https://github.com/chuckb/riscv-helloworld （找 assembly 版本）
- 实操：clone 仓库，研究里面的 `Makefile`、`baremetal.ld`、`hello.s`。
  - 尝试拆成多个 .s 文件（一个放 puts 函数，一个放 main），改 Makefile 加入多目标编译。
  - 加 GDB 调试：学会 `make debug` 或手动 `qemu -s -S` + `gdb-multiarch`。

这一步让你真正感受到“工程”：不再是手动敲 as/ld 命令，而是 `make` 一键构建。

**Day 5-7：深入链接脚本 + 启动代码（Tyler Wilcock 系列，最推荐）**

- 博客系列（经典，必看）：
  - Part 1：工具链 + 简单 C（https://twilco.github.io/riscv-from-scratch/2019/03/10/riscv-from-scratch-1.html）
  - Part 2：硬件布局、**linker scripts**、**crt0 启动代码**（https://twilco.github.io/riscv-from-scratch/2019/04/27/riscv-from-scratch-2.html）
- 实操：
  - 手写或修改 `crt0.s`（_start：设置 sp、gp、清 bss、调用 main）。
  - 自定义 `linker.ld`（定义 MEMORY、SECTIONS，放置 .text、.data、.bss、.rodata）。
  - 从纯汇编切换到混用 C + 汇编（写一个 C 函数，让汇编调用）。
- 每天目标：改一次链接脚本或启动代码，看 QEMU 输出是否变化，用 objdump/nm 验证符号地址。

**第1周结束检查**：你应该能自己新建一个目录，包含：

- src/（放 .s 或 .c）
- linker.ld
- Makefile（支持 clean/build/run/debug）
- 跑通输出字符串或简单循环。

### 第2周：多文件工程实践 + 裸机小项目（真正“组织成工程”）

**Day 8-10：切换到更完整的 starter 或 USTC 风格**

- 推荐 clone 一个干净的 bare metal 模板练习组织：

  - https://github.com/chuckb/riscv-helloworld-c （C 版本，结构清晰，有 GDB/VSCode 支持）
  - 或 https://github.com/noteed/riscv-hello-c （极简 hello）
- 实操任务：

  1. 把你的第1周代码迁移进去。
  2. 增加目录结构：`src/asm/`（启动 + 汇编函数）、`src/lib/`（uart_puts 等）、`include/`。
  3. Makefile 支持 `make all`、`make run`、`make debug`、`CFLAGS` 控制优化。
  4. 实现一个简单 `uart.c` + `uart.h`，用汇编或 C 写 `putchar`/`puts`。
- 如果想更系统，参考 USTC CECS-Lab（中文，实验导向）：

  - https://github.com/USTC-System-Courses/CECS-Lab （找 lab1 裸机部分）
  - 它有 base-port，提供现成启动 + MMIO 抽象，适合你快速扩展。

**Day 11-13：小项目实战（综合组织能力）**
建议做 2-3 个 progressively 复杂的小程序：

1. **串口回显**：接收键盘输入，输出回去（轮询 UART 状态寄存器）。
2. **简单计算器**：汇编实现加减法，用串口输入输出（练习函数调用、栈）。
3. **异常/中断入门**（可选）：加一个简单 trap 处理（打印 "trap!"）。

每次都注意：

- 如何把功能拆成多个文件（.s 或 .c）。
- 链接脚本如何控制段对齐/地址。
- Makefile 如何自动依赖（`%.o: %.s` 规则）。

**Day 14：回顾 + 搭建自己的框架**

- 整理一个“我的 RISC-V 裸机模板”仓库：
  - 包含 crt0.s、linker.ld、uart 驱动、Makefile。
  - 写 README 记录你踩过的坑（这很重要，以后复用）。
- 尝试加 GDB 断点单步，观察寄存器、内存。

### 常见坑 & 建议

- 地址不对 → 检查 linker.ld 的 ENTRY(_start) 和 MEMORY 区域。
- 栈没设 → 程序崩溃（在 _start 里 `la sp, stack_top`）。
- 多文件链接报错 → 用 `riscv64-unknown-elf-ld -Map map.txt` 生成 map 文件看布局。
- 每天跑 `make clean && make` 养成习惯。
- 用 `objdump -d`、`nm`、`readelf -h` 多看 ELF 文件。
