# RISC-V 时钟中断机制（硬件篇）

我给你**彻底梳理清楚 RISC-V 时钟中断的硬件原理**，不讲废话、不绕弯，完全聚焦**硬件结构 + 寄存器 + 触发流程**，这是理解时钟中断、编写定时器代码的核心基础。

RISC-V 的时钟中断**完全由硬件定义**，属于**机器模式（M-Mode）专用中断**，是 RISC-V 架构标准里最核心、最稳定的定时器机制。

---

# 一、核心硬件组件（必须记住）

RISC-V 时钟中断由 **3 个硬件模块 + 4 个关键寄存器** 构成：

## 1. 硬件模块

1. **mtime 寄存器**：**系统全局实时计数器**

   - 64 位只读寄存器
   - 由板级晶振驱动，**永不停止、永不复位**（除非系统断电）
   - 每个时钟周期 +1
   - 全 CPU 核心共享一个全局 mtime
2. **mtimecmp 寄存器**：**每个核心独立的比较寄存器**

   - 64 位读写寄存器
   - **每个 Hart（CPU 核心）一个独立 mtimecmp**
   - 硬件功能：当 `mtime >= mtimecmp` 时，**自动触发时钟中断**
3. **中断信号发生器**

   - 硬件比较器：持续比较 `mtime` 和 `mtimecmp`
   - 满足条件 → 向对应核心**发送机器模式定时器中断（MTIP）**

---

# 二、4 个关键硬件寄存器

## 1. `mtime`（全局时钟计数器）

- 地址：由芯片手册定义（内存映射寄存器）
- 功能：**硬件自动递增**，记录系统运行时间
- 特性：
  - 64 位
  - 全核心共享
  - 只读（软件不能写，只能读）

## 2. `mtimecmp`（每核独立比较器）

- 地址：每个核心偏移不同
- 功能：**写它 = 开启下一次时钟中断**
- 规则：
  ```
  if (mtime >= mtimecmp) {
      触发时钟中断
  }
  ```
- 特性：
  - 64 位
  - 每个 Hart 独立
  - 上电默认值 = 0xFFFFFFFFFFFFFFFF（最大，不触发中断）

## 3. `mip`（中断等待寄存器）

- **第7位 MTIP = Timer Interrupt Pending**
- 硬件自动置 1：当 `mtime >= mtimecmp`
- 硬件自动清 0：当 `mtimecmp > mtime`（软件重写 mtimecmp 即可清除）
- **软件不能直接写 MTIP，只能通过 mtimecmp 间接控制**

## 4. `mie`（中断使能寄存器）

- **第7位 MTIE = Timer Interrupt Enable**
- 软件写 1：**使能时钟中断**
- 软件写 0：关闭时钟中断

# 三、硬件触发时钟中断的完整流程（最关键）

我用**硬件视角**给你走一遍：

1. **晶振振荡 → mtime 硬件自动 +1**
2. 软件向 **mtimecmp** 写入一个未来值：
   ```
   mtimecmp = mtime + 周期值
   ```
3. 硬件比较器**持续监测**
4. 当 `mtime 增加到 ≥ mtimecmp`
5. **硬件自动将 mip.MTIP 置 1**
6. 如果 mie.MTIE = 1 且 mstatus.MIE = 1
7. **CPU 立即跳转到机器模式异常入口（mtvec）执行中断服务**
8. 软件在中断里**重新设置 mtimecmp**
9. 硬件看到 mtimecmp > mtime → **自动清 0 MTIP**
10. 下一轮周期开始

---

# 四、最重要的硬件特性（面试/开发必考）

1. **时钟中断是 RISC-V 架构标准，不是外设中断**
2. **每个核心独立触发、独立处理**
   - 你写核心0的mtimecmp，只会触发核心0的中断
3. **mtime 全局唯一，mtimecmp 每核一个**
4. **MTIP 位硬件自动置位/自动清除**
   - 软件不能直接写 mip 来清中断
   - 清中断唯一方法：**写 mtimecmp 为更大的值**
5. **时钟中断只能在 M-Mode 接收**
   - S-mode/U-mode 不能直接处理
   - 必须由 M-mode 转发

---

# 五、硬件中断信号编号

RISC-V 标准定义：

- **机器模式时钟中断：Interrupt 7**
  - mip.MTIP (bit 7)
  - mie.MTIE (bit 7)

这是固定的，所有 RISC-V 芯片都一样。

---

# 六、最简硬件工作模型（一眼看懂）

```
晶振 → mtime（自动+1）
            ↓
mtime 与 mtimecmp 比较
            ↓
mtime ≥ mtimecmp → MTIP=1 → 触发时钟中断
            ↓
软件重写 mtimecmp → MTIP=0 → 等待下一轮
```

---

# 七、一句话总结硬件机制

**RISC-V 时钟中断 = 全局 64 位计数器 mtime 与每核独立 64 位比较器 mtimecmp 硬件比较，满足条件自动触发机器模式中断，MTIP 位硬件自动管理。**

---

### 总结

- **mtime**：硬件自动计时
- **mtimecmp**：每核独立、写它=设置下一次中断
- **MTIP**：硬件自动置1/清0，软件不能直接改
- **中断触发条件**：`mtime ≥ mtimecmp`
- **清中断方法**：重写 mtimecmp
- **只能在 M-Mode 处理**
