RISC-V CSR（控制与状态寄存器）按**特权级别**划分，有严格的**地址编码、访问权限、读写规则**，下面从分类、常用寄存器、设置规则三方面讲透。

---

## 一、CSR 基础：地址与权限编码（核心）

CSR 用 **12 位地址（0x000–0xFFF）**，共 4096 个地址空间。地址高 4 位（`csr[11:8]`）编码**读写权限 + 最低可访问特权级**：

### 1. 地址编码规则

- **`csr[11:10]`（读写权限）**
  - `00/01/10`：**可读写（RW）**
  - `11`：**只读（RO）**
- **`csr[9:8]`（最低特权级）**
  - `00`：用户模式（U-mode）
  - `01`：监管模式（S-mode）
  - `10`：虚拟机监控器模式（H-mode）
  - `11`：机器模式（M-mode，最高权限）

### 2. 访问规则

- 高特权级可访问低特权级 CSR，反之不行。
- 访问不存在的 CSR / 越权访问 / 写只读 CSR → 触发**非法指令异常**。
- 可读写 CSR 可能含只读位，写只读位会被**忽略**。

---

## 二、按特权级分类：常用 CSR 清单

### 1. 机器模式（M-mode，0x300–0x3FF）

最核心、权限最高，系统启动/异常/中断必用：

| 地址  | 名称           | 权限 | 核心功能                                                   |
| :---- | :------------- | :--- | :--------------------------------------------------------- |
| 0x300 | `mstatus`    | MRW  | 全局状态：全局中断使能（MIE）、特权级切换（MPP）、浮点状态 |
| 0x304 | `mie`        | MRW  | M级中断使能（软件/定时器/外部中断）                        |
| 0x305 | `mtvec`      | MRW  | 异常/中断入口基地址（支持直接/向量模式）                   |
| 0x306 | `mcounteren` | MRW  | 性能计数器使能（控制U/S级能否读计数器）                    |
| 0x340 | `mscratch`   | MRW  | 临时 scratch 寄存器（上下文切换用）                        |
| 0x341 | `mepc`       | MRW  | 异常发生时的 PC（异常返回地址）                            |
| 0x342 | `mcause`     | MRW  | 异常/中断原因码（最高位=1表示中断）                        |
| 0x343 | `mtval`      | MRW  | 异常附加信息（如访存错误地址）                             |
| 0x344 | `mip`        | MRO  | M级中断挂起状态（只读，硬件置位）                          |

### 2. 监管模式（S-mode，0x100–0x1FF）

操作系统内核用，支持虚拟内存与用户态隔离：

| 地址  | 名称           | 权限 | 核心功能                                      |
| :---- | :------------- | :--- | :-------------------------------------------- |
| 0x100 | `sstatus`    | SRW  | S级状态（中断使能、特权级、浮点）             |
| 0x104 | `sie`        | SRW  | S级中断使能                                   |
| 0x105 | `stvec`      | SRW  | S级异常入口                                   |
| 0x106 | `scounteren` | SRW  | S级计数器使能                                 |
| 0x120 | `sepc`       | SRW  | S级异常返回PC                                 |
| 0x121 | `scause`     | SRW  | S级异常原因                                   |
| 0x122 | `stval`      | SRW  | S级异常附加信息                               |
| 0x123 | `sip`        | SRO  | S级中断挂起                                   |
| 0x180 | `satp`       | SRW  | 地址转换与保护（页表基址、模式：Sv39/Sv48等） |

### 3. 用户模式（U-mode，0x000–0x0FF）

用户态可用，主要是计数器与浮点状态：

| 地址         | 名称                                               | 权限 | 核心功能                                      |
| :----------- | :------------------------------------------------- | :--- | :-------------------------------------------- |
| 0xC00–0xC1F | `cycle`/`time`/`instret`/`hpmcounter3–31` | URO  | 性能计数器（周期/时间/指令 retired/硬件性能） |
| 0x001        | `fflags`                                         | URW  | 浮点异常标志                                  |
| 0x002        | `frm`                                            | URW  | 浮点舍入模式                                  |
| 0x003        | `fcsr`                                           | URW  | 浮点控制状态（`fflags`+`frm`）            |

### 4. 虚拟机监控器（H-mode，0x600–0x6FF）

虚拟化扩展，管理虚拟机，如 `hstatus`/`hedeleg`/`hideleg`/`hvip`/`hstvec`/`hgatp` 等。

## 三、CSR 设置规则（读写与字段行为）

### 1. 原生 CSR 指令（Zicsr 扩展）

只有 3 条原子读-改-写指令，所有伪指令（`csrr`/`csrw`）都展开为这 3 条：

1. `csrrw rd, csr, rs1`：**读-改写**（rd=CSR，CSR=rs1）
2. `csrrs rd, csr, rs1`：**读-置位**（rd=CSR，CSR |= rs1）
3. `csrrc rd, csr, rs1`：**读-清零**（rd=CSR，CSR &= ~rs1）

### 2. 字段读写行为（必须遵守）

RISC-V 定义 3 种字段行为，写操作必须遵循：

- **WPRI（Write Preserve, Read Ignore）**
  - 保留位：读忽略，写必须保持原值（不能改）。
  - 例：`mstatus` 中未定义位，写时需先读再保留。
- **WARL（Write Any, Read Legal）**
  - 写任意值，读返回合法值（硬件自动修正非法值）。
  - 例：`mtvec` 模式位（MODE），写非法值硬件转为合法模式。
- **WLRL（Write Legal, Read Legal）**
  - 只能写合法值，否则行为未定义；读返回最后写入的合法值。
  - 例：`satp` 模式位（MODE），必须写 Sv39/Sv48 等合法值。

### 3. 读写操作规范

1. **读 CSR**
   - 用 `csrr rd, csr`（伪指令 → `csrrs rd, csr, x0`）。
   - 读无副作用（除少数调试/性能计数器）。
2. **写 CSR**
   - 用 `csrw csr, rs`（伪指令 → `csrrw x0, csr, rs`）。
   - 写前**必须先读**，保留 WPRI 位，只修改目标位。
   - 例：使能 M 级全局中断（`mstatus.MIE`）：
     ```asm
     csrr  t0, mstatus    # 读mstatus到t0
     li    t1, 0x8        # MIE位（bit3）
     or    t0, t0, t1     # 置位MIE
     csrw  mstatus, t0    # 写回mstatus
     ```
3. **位操作（置位/清零）**
   - 置位：`csrs csr, rs` → `csrrs x0, csr, rs`
   - 清零：`csrc csr, rs` → `csrrc x0, csr, rs`
   - 例：清零 `mie.MTIE`（定时器中断使能）：
     ```asm
     li    t0, 0x80       # MTIE位（bit7）
     csrc  mie, t0        # 清零mie的MTIE位
     ```

### 4. 立即数形式（Zicsr 扩展）

支持 5 位立即数直接操作，无需通用寄存器：

- `csrrwi rd, csr, imm`（改写）
- `csrrsi rd, csr, imm`（置位）
- `csrrci rd, csr, imm`（清零）
  例：`csrrsi x0, mstatus, 0x8` → 直接置位 `mstatus.MIE`。

## 四、常见陷阱与最佳实践

1. **不要直接写全 0/全 1**
   - 很多 CSR 含 WPRI 保留位，直接写 0 会破坏系统状态。
   - 正确：先读 → 改目标位 → 写回。
2. **权限检查**
   - U 态不能访问 M/S 级 CSR，否则触发异常。
3. **异常/中断上下文**
   - 异常处理中必须保存/恢复 `mstatus`/`mepc`/`mcause` 等。
4. **WARL/WLRL 区别**
   - WARL：写错硬件会修正；WLRL：写错行为未定义（必须合法）。

---

## 五、速记总结

- **地址**：12 位，高 4 位定权限与特权级。
- **指令**：3 条原生 + 伪指令，原子读-改-写。
- **规则**：WPRI 保留、WARL 容错、WLRL 严格合法；写前必读、保留保留位。
- **核心 CSR**：M 级（`mstatus`/`mie`/`mtvec`/`mepc`）、S 级（`satp`）、U 级（计数器/浮点）。
