下面我把 **RISC-V 异常/中断到底怎么从硬件层面被“点燃”** 从头到尾讲细，包括：

- 内部异常（指令本身出错）
- 外部中断（外设、GPIO、定时器）
- 硬件内部信号线路
- 从“引脚电平变化”到“CPU 跳 mtvec”的完整链路

不讲虚的，全部是**硬件真实行为**。

---

# 0. 先分清两类触发源（RISC-V 架构严格区分）

## 1）异常 Exception —— **来自 CPU 内部**

由**当前执行的指令自身**产生。

- 非法指令
- 除以零
- 取指令/读数据地址错误（访存异常）
- ecall 调用（主动进异常）
- ebreak 断点

## 2）中断 Interrupt —— **来自 CPU 外部**

由**外部设备信号**触发，与当前指令无关。

- 定时器中断（MTIMER）
- 外部中断（PLIC 来的）
- UART 接收完成
- GPIO 上升/下降沿
- SPI/DMA 完成

---

# 1. 内部异常：硬件是怎么被触发的？（最细）

内部异常 = **指令执行单元自己发现错误**

CPU 执行一条指令时，内部至少分这几步：

1. 取指 IF
2. 译码 ID
3. 执行 EX
4. 访存 MEM
5. 写回 WB

**任意一步检测到错误 → 直接触发异常**

## 1.1 取指令阶段触发（Instruction Fault）

```
PC 指向非法地址（未映射、无权限、未对齐）
↓
总线返回 SLVERR/DECERR
↓
CPU 内部的“错误检测逻辑”拉高异常信号
↓
流水线立刻停止
↓
进入异常响应流程
```

对应 mcause：

- **Instruction Access Fault**

## 1.2 译码阶段触发

```
指令编码是全0、或保留值
↓
译码器发现“不认识的指令”
↓
直接触发异常
```

对应：

- **Illegal Instruction 异常**

## 1.3 执行阶段触发

```
执行 DIV 指令，除数为 0
↓
ALU 内部检测到 divide by zero
↓
触发异常
```

对应：

- **Breakpoint**（ebreak）
- **Environment Call**（ecall）
- **Illegal Instruction**

## 1.4 访存阶段触发

```
lw/sw 访问非法地址
地址未对齐（RISC-V 不强制，但部分平台会异常）
访问无权限区域（U 模式访问 M 模式区域）
↓
总线异常 → CPU 异常信号拉高
```

对应：

- **Load Access Fault**
- **Store Access Fault**
- **Load Address Misaligned**

## 1.5 主动触发异常（ecall / ebreak）

```
执行 ecall
↓
译码器识别为“环境调用”
↓
直接触发异常
```

用途：

- FreeRTOS 任务切换用 **ecall 软件触发异常**
- 调试用 ebreak

# 2. 外部中断：硬件如何从“外设信号”传到 CPU？（超级关键）

外部中断不走指令流水线，走**独立硬件线路**。

完整路径：

```
外设引脚/模块
    ↓
外设中断请求线 IRQn
    ↓
PLIC (Platform-Level Interrupt Controller)
    ↓
PLIC 向 CPU 发出 MEIP / SEIP / UEIP 中断请求信号
    ↓
CPU 内部中断检测采样
    ↓
满足条件 → 触发中断
```

## 2.1 第一步：外设产生中断信号

例如：

- UART 收到一个字节 → 拉高 UART_IRQ
- GPIO 上升沿 → 拉高 GPIO_IRQ
- 定时器计数满 → MTIMER 拉高中断

这些都是**单纯的电平/脉冲信号**，和 CPU 无关。

## 2.2 第二步：进入 PLIC（中断集线器）

PLIC 做：

- 多路中断输入
- 优先级仲裁
- 去抖动
- 屏蔽控制
- 最终只输出 **少量几根线到 CPU**

PLIC 输出给 CPU 的信号只有几个：

- **MEIP**：M 模式外部中断请求
- **SEIP**：S 模式
- **UEIP**：U 模式

真正硬件上就是 **一根线拉高**。

## 2.3 第三步：CPU 内部采样中断信号

CPU 每个指令周期都会**采样中断请求线**：

```
时钟上升沿
    ↓
采样 MEIP（是否为高）
    ↓
检查 mstatus.MIE 是否为 1
    ↓
检查 mie.MEIE 是否允许该中断
    ↓
满足 → 触发中断
```

## 2.4 中断与指令的关系（非常重要）

**中断不是立刻打断当前指令！**
硬件规则：

- 必须等**当前指令完成**
- 再进入中断
  不会执行一半指令跳走。

# 3. 硬件触发后，CPU 统一做的“异常响应微架构动作”

不管是内部异常还是外部中断，**触发后硬件行为完全一致**：

## 3.1 停止流水线

如果是异常：

- 放弃当前指令的写回
- 清空流水线

如果是中断：

- 等当前指令正常退休

## 3.2 记录 CSR

```
mepc      = 被打断的指令 PC
mcause    = 异常/中断编号
mstatus.MPP = 当前特权级
mstatus.MPIE = mstatus.MIE
mstatus.MIE = 0 （关中断）
```

## 3.3 跳转到 mtvec

```
PC = mtvec
```

从此进入软件异常入口。

---

# 4. 内部异常 vs 外部中断：触发方式对比（最清晰）

## 内部异常 Exception

- 来源：**CPU 内部逻辑**
- 触发点：**指令执行过程中**
- 同步：和指令严格同步
- 不可屏蔽：错误发生就一定进异常
- 例子：非法指令、除零、ecall、访存错误

## 外部中断 Interrupt

- 来源：**外部 PLIC 信号**
- 触发点：**指令边界**
- 异步：随时可能来
- 可屏蔽：mstatus.MIE + mie.MEIE 控制
- 例子：UART、GPIO、定时器、以太网

# 5. 最核心的硬件信号（真正底层）

你在 RTL/芯片手册里会看到这些真实信号：

- **intr_req**：中断请求
- **excp_req**：异常请求
- **excp_code**：异常类型编码
- **mtvec_base**：异常入口地址
- **mepc_we**：写 mepc 使能
- **mcause_we**：写 mcause 使能

触发时：

1. `excp_req = 1`
2. 组合逻辑输出 `excp_code`
3. 寄存器堆写入 mepc/mcause/mstatus
4. 下周期 PC = mtvec

---

# 6. 一句话终极总结（硬核版）

- **内部异常**：指令执行时，CPU 内部组合逻辑检测错误 → 拉高异常请求 → 同步触发。
- **外部中断**：外设 → PLIC → 拉高 MEIP 线 → CPU 每个周期采样 → 指令边界异步触发。
- 触发后硬件统一做：保存 mepc/mcause/mstatus → 关中断 → 跳 mtvec。
