# 0. 前置知识：必须记住的 4 种特权级

RISC-V 有 **4 个特权级**，异常处理只用到：

- **M 模式（Machine）**：最高权限，硬件异常全部进 M 模式
- **U 模式（User）**：用户程序（FreeRTOS 任务运行在 U 或 M）

**所有异常/中断，硬件都会强制进入 M 模式**

---

# 1. 异常发生前：运行状态（重要）

假设：

- CPU 目前在 **U 模式（用户/任务）**
- **MIE = 1**（全局中断使能）
- **mtvec** 已经设置为异常入口地址
- 当前指令地址 = **PC**

关键 CSR：

- `mstatus.MIE` = 1（M 模式全局中断使能）
- `mstatus.MPP` = 01（表示之前是 U 模式）
- `mepc` = 无效
- `mcause` = 无效

---

# 2. 异常/中断触发：硬件自动执行 6 步（不可修改）

当异常发生（除零、非法指令、外设中断），**硬件立即自动执行以下步骤**：

## 2.1 停止当前指令

- 未执行完：丢弃
- 已执行完：PC 已自增

## 2.2 保存**当前特权级**到 `mstatus.MPP`

- MPP = **当前模式**
  - U 模式 → MPP = 01
  - M 模式 → MPP = 11

作用：**mret 时知道回到什么特权级**

## 2.3 保存**当前全局中断使能 MIE** 到 `mstatus.MPIE`

- `MPIE = MIE`
- 把旧的中断使能状态存起来

## 2.4 关闭全局中断，防止嵌套

- `MIE = 0`
  进入异常后**默认关闭中断**

## 2.5 写入 2 个关键 CSR

1. **`mepc` = 当前 PC**
   保存被打断的指令地址
2. **`mcause` = 异常/中断编号**
   - 最高位 = 1 → 中断
   - 最高位 = 0 → 异常

## 2.6 硬件强制跳转到异常入口

**PC = mtvec**
进入软件定义的异常处理函数

---

# 3. 此时 CSR 状态总结（关键）

```
mstatus.MIE   = 0    （中断关闭）
mstatus.MPIE  = 旧值（1）
mstatus.MPP   = 01   （来自 U 模式）
mepc          = 被打断的指令地址
mcause        = 异常/中断原因
mtvec         = 异常处理入口
```

---

# 4. 软件异常入口（汇编代码）

硬件跳转到 `mtvec` 后，执行第一行汇编：

## 4.1 立即保存上下文（你之前看到的宏）

```asm
portcontextSAVE_CONTEXT_INTERNAL:
    addi sp, sp, -portCONTEXT_SIZE
    store_x x1,  2*portWORD_SIZE(sp)
    store_x x5 ... 所有寄存器
    ...
```

### 必须保存：

- x1~x31 通用寄存器
- mstatus
- mepc
- xCriticalNesting

**不保存这些，任务无法恢复！**

---

# 5. 软件：解析异常原因（C 语言）

```c
void trap_handler(void)
{
    uint32_t cause = mcause;
    int is_interrupt = (cause >> 31) & 1;
    int code = cause & 0x7FFFFFFF;

    if (is_interrupt) {
        // 中断处理：定时器、UART、以太网
        if (code == 7) timer_handler();  // M 模式定时器
        if (code == 11) external_irq();   // 外部中断
    } else {
        // 异常处理：除零、非法指令、缺页
        panic(mepc, mstatus);
    }
}
```

---

# 6. 异常返回：执行 mret（硬件自动恢复 4 步）

处理完后，软件执行：

```asm
mret
```

**硬件自动做 4 件事：**

## 6.1 恢复特权级

**当前特权级 = mstatus.MPP**

- MPP=01 → 回到 U 模式
- MPP=11 → 回到 M 模式

## 6.2 恢复全局中断使能

**mstatus.MIE = mstatus.MPIE**
把之前保存的中断使能恢复

## 6.3 清零 MPIE（准备下一次异常）

**MPIE = 1**（标准行为）

## 6.4 跳回被打断的指令

**PC = mepc**
程序继续执行

---

# 7. mret 后最终状态

```
mstatus.MIE = 恢复为原来的值（1）
特权级 = 原来的 U/M 模式
PC = mepc（继续执行）
中断恢复
```

---

# 8. 最重要 CSR 寄存器逐位解释（必背）

## mstatus（机器状态寄存器）

| 位             | 名字               | 作用         |
| -------------- | ------------------ | ------------ |
| **MIE**  | M 模式全局中断使能 | 1=开，0=关   |
| **MPIE** | 异常前的 MIE       | 硬件自动保存 |
| **MPP**  | 异常前特权级       | 01=U，11=M   |

## mtvec

- 异常入口地址
- 直接写异常处理函数地址

## mepc

- 异常返回地址
- 被打断指令的 PC

## mcause

- 最高位：1=中断，0=异常
- 低 31 位：异常编号

---

# 9. 特权级切换完整路径（最清晰）

```
U 模式（任务运行）
→ 异常触发
→ 硬件自动：MPP=U，MPIE=MIE，MIE=0
→ 进入 M 模式（异常处理）
→ 执行 mret
→ 硬件恢复：特权级=U，MIE=MPIE
→ 回到 U 模式继续运行
```

---

# 10. 最精简硬核总结（面试/看源码必背）

## 硬件做什么：

1. 保存特权级到 MPP
2. 保存中断使能到 MPIE
3. 关闭 MIE
4. 写 mepc = PC
5. 写 mcause = 原因
6. 跳转到 mtvec

## 软件做什么：

1. 保存所有寄存器到栈
2. 解析 mcause
3. 执行中断/异常处理
4. 恢复寄存器
5. 执行 mret

## mret 做什么：

1. 恢复特权级
2. 恢复 MIE
3. PC = mepc
